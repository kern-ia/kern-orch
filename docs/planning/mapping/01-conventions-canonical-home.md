# Question

`CONVENTIONS.md` already exists at the repository root. It declares itself "local authority
for this repo, as announced by the org-wide CONTRIBUTING.md" of `kern-ia`, and the same file
is being rolled out across the other `kern-ia` repositories. The lx pipeline expects its
conventions deliverable at `docs/planning/CONVENTIONS.md`, and every downstream skill
(`define-change`, `create-issues`, `implement-issue`, `review-implementation`) reads that
path. Two files describing the same rules will drift apart.

# Options

- **Root stays the single editable authority; `docs/planning/CONVENTIONS.md` is a derived
  snapshot** carrying `mapped_commit`, stating in its first line that the root file is
  authoritative and that it is regenerated by re-running the mapping. Preserves the org-wide
  rollout; costs one regeneration step whenever the root file changes.
- **Move the content into `docs/planning/CONVENTIONS.md`, leave a one-line pointer at the
  root.** One home for the fact, but breaks the uniformity the org rollout is establishing
  across the ten `kern-ia` repos.
- **Keep only the root file and skip the deliverable.** Least duplication, but downstream lx
  skills read a path that does not exist and silently lose the conventions.

# Recommendation

The first option. The org-wide rollout of a root `CONVENTIONS.md` is active work across ten
repositories, and diverging here for one tool's path convention is the wrong trade. Marking
the planning copy as derived — with the commit it was derived from — makes the drift
detectable instead of silent.

# Verdict

Root stays the single editable authority; `docs/planning/CONVENTIONS.md` is a derived snapshot.

The planning copy carries `mapped_commit` and states on its first line that the root file is
authoritative and that it is regenerated by re-running `map-codebase`. The org-wide rollout of a
root `CONVENTIONS.md` across the ten `kern-ia` repositories is preserved, and drift between the
two files stays detectable through the recorded commit.
